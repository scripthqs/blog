# AI Agent

## 范式变化

### 前端成为 Agent 执行层

AI 不能直接操作浏览器环境，所有可执行行为必须通过前端提供的工具函数完成，例如：

- 路由跳转
- DOM 操作
- 表单填写
- 弹窗交互
- 可视化渲染

因此：

| 角色 | 职责     |
| ---- | -------- |
| 模型 | 负责决策 |
| 前端 | 负责执行 |

Agent 逻辑不只存在前端。生产系统通常是：客户端负责执行，服务端负责编排与安全控制。

前端不只是 UI 层，而是 **Agent 的行为运行环境**。

---

### 交互范式变化

| 类型    | 模式             |
| ------- | ---------------- |
| 传统    | 用户学习系统结构 |
| AI 系统 | 系统适应用户意图 |

表现形式：

- 意图驱动界面
- 生成式界面
- 自然语言控制应用

---

### 前端职责扩展

**传统职责：**

- 组件开发
- 状态管理
- 接口调用

**新增职责：**

- 工具设计与描述
- Prompt 设计
- Agent 流程控制
- 模型输出约束
- 成本与延迟优化
- 安全与权限控制

> **核心变化：** 前端从展示层升级为**交互编排层**。

---

## 系统架构

标准 AI Agent Web 架构：

```json
用户输入
  ↓
前端上下文收集
  ↓
服务端 AI 编排层
  ↓
大模型推理
  ↓
工具调用决策
  ↓
前端执行工具
  ↓
结果反馈模型
```

**关键原则：**

- 模型负责思考
- 系统负责约束
- 前端负责执行

## 核心技术栈

### Vercel AI SDK

**作用：** 统一模型调用与流式交互框架

**核心能力：**

- 流式输出
- 工具调用处理
- 多模型统一接口
- 前端友好 API

**关键接口：**

- `streamText`
- `onFinish`
- `tool handling`

> **工程价值：** 降低 AI 应用开发复杂度。

---

### Zod 结构化输出约束

**问题：** 模型输出本质是非结构化文本。

**解决方案：** 用 Schema 强制结构化数据。

**作用：**

- 函数调用参数校验
- JSON 输出约束
- 类型安全
- 降低解析错误率

> ⚠️ **重要原则：** 不要信任模型输出，必须做结构验证。

---

### LangChain 工作流框架

**适用场景：** 复杂多步骤 AI 系统。

**主要能力：**

- 对话记忆管理
- 多步流程编排
- 工具选择逻辑
- 检索系统集成

> **注意：** 简单应用不需要 LangChain，优先使用轻量方案。

## 大模型应用核心机制

### Tool Calling

模型不直接执行操作，只生成调用指令。

**执行流程：**

```json
定义工具描述 → 模型选择工具 → 系统执行函数 → 结果返回模型
```

> **本质：** AI 变成可控函数调度器。

---

### 生成式 UI

- 模型输出界面结构描述
- 前端根据描述渲染组件

**实现形式：**

- 组件类型
- 参数数据
- 布局信息

> **重要修正：** 生产系统通常不会完全由模型决定 UI，应使用**白名单组件系统**。

---

### 上下文管理

**大模型天然限制：**

- 上下文窗口有限
- 无长期记忆
- 可能产生幻觉

**工程解决方案：**

| 方案     | 说明           |
| -------- | -------------- |
| 对话摘要 | 压缩历史对话   |
| 滑动窗口 | 保留最近 N 轮  |
| 知识检索 | 外部注入上下文 |
| 结果验证 | 校验模型输出   |

---

## RAG 检索增强生成

**目标：** 让模型基于真实数据回答。

**工作流程：**

```json
问题输入 → 检索知识 → 上下文注入 → 模型生成
```

### 文档处理

文档必须分块处理，推荐策略：

- ✅ 语义分块
- ✅ 重叠分块
- ❌ 避免固定长度硬切

### 向量化

文本转为语义向量表示，用途：

- 相似度搜索
- 语义匹配
- 知识定位

### 存储方案

| 场景     | 方案                      |
| -------- | ------------------------- |
| 小规模   | 前端向量库 / 内存检索     |
| 生产环境 | 向量数据库 / 混合检索系统 |

### 检索优化策略

**提升召回：**

- 多查询改写
- 假设答案检索

**提升准确：**

- 关键词检索
- 混合搜索
- 结果重排序

> ⚠️ **重要原则：** 检索质量决定 AI 上限。

## Agent 工作流模型

推荐执行模式（ReAct 模式）：

```json
意图解析 → 问题改写 → 知识检索 → 推理生成
                                      ↓
                        结果反馈 ← 执行操作 ← 工具决策
```

> 该模式属于：**推理与行动结合系统（ReAct）**。

---

## 工程级稳定性设计

### 人工确认机制

敏感操作必须人工确认，前端职责：

- 拦截执行
- 展示理由
- 等待授权

### 记忆策略

长对话必须压缩，常用方法：

- 自动摘要
- 滑动窗口
- 长期存储

### 稳定性控制

必须实现：

- [ ] 重试机制
- [ ] 输出校验
- [ ] 降级策略
- [ ] 错误恢复

### 可观测性

AI 系统必须可调试，建议记录：

- 模型输入
- 模型输出
- 工具调用
- 推理过程

## 本质总结

需要给AI划定清晰的职责边界

AI Agent Web 应用的本质结构：

| 层级     | 能力             |
| -------- | ---------------- |
| 大模型   | 提供认知能力     |
| 检索系统 | 提供真实知识     |
| 工具系统 | 提供执行能力     |
| 前端     | 提供行为运行环境 |
| 编排层   | 控制流程         |

> 系统不再是固定逻辑程序，而是**目标驱动的概率系统**。
